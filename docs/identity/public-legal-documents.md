# Public legal documents and registration

The canonical bilingual sources follow the chosen convention `docs/legal/terms/<version>/<locale>.md` and `docs/legal/privacy/<version>/<locale>.md`, with active versions in `docs/legal/catalog.json`. The derived `backend/src/Duora.Infrastructure/Identity/LegalDocuments/catalog.json` is embedded in the application assembly. Regenerate it with `python3 scripts/supply-chain/legal_documents.py --write`; the existing supply-chain gate checks exact canonical-source parity. Runtime builds consume this checked artifact without requiring a document CMS or a different Docker context. `GET /api/v1/legal-documents` is an exact anonymous read, with `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. It grants no other public API access. `/terms` and `/privacy` select the current document in the interface language; `/terms/:version/:documentLocale` and `/privacy/:version/:documentLocale` resolve an exact retained version and language, without silent substitution.

The active Terms are version `2026-10-29` (PT-BR and EN-US). Its only content change from `2026-10-25` is the "Minimum age" section: the service is only for people aged 18 or older, and registrants declare that they are 18 or older ([decision record](../product/decisions-2026-10-29.md), item 1). This requirement is product coherence with the spec; it is **not** age verification and **not** compliance with Brazil's ECA Digital, which had no legal opinion and whose cited text rejects self-declaration.

Each active document must have both `pt-BR` and `en-US` variants, meaningful text, the same identified controller and public contact, and explicit source approval. Missing, duplicate, invalid or unapproved variants keep registration closed (503). With the current approved source, the publication gate no longer blocks `POST /api/v1/auth/register`. Existing login and account recovery are unaffected by this gate. The legal gate is not the only condition for real participants: deployment, delivery of the confirmation email (the production compose still uses the pickup directory, and an external email provider must first be named in a new privacy version) and the other operational gates keep their own authorization; green CI alone does not authorize activation.

## Exact acceptance

The public catalog is revalidated on mount and focus without a timer or automatic retry; stale readiness cannot remain indefinitely cached across visits. The registration form appears only after a valid published catalog. Each document has its own language selector and exact versioned link. The user interface language does not rewrite document metadata. Changing a document identity clears the form and acceptance; it also cancels pending public operations before CSRF can continue to registration. Credentials remain component-local and are not mutation variables.

The request sends each document's version, locale and SHA-256, plus `confirmedAdult: true` from the explicit "I declare that I am 18 or older" checkbox. Missing, `null` or `false` is a 400 `VALIDATION_FAILED` before any write; no age or birth date is collected. The declaration is recorded only through the Terms consent row (version, locale and digest of a text that contains it). There is no re-acceptance flow: existing accounts keep their earlier Terms acceptance until one is built. The digest is over UTF-8 bytes of the canonical web JSON object in this property order: `document`, `version`, `locale`, `title`, `controllerName`, `privacyContact`, `sections` (section property order `title`, `paragraphs`). The .NET web JSON escaping and compact serialization define the bytes. Approval is excluded from content identity. Clients use the digest returned by the server rather than reconstructing serialization.

The endpoint validates the active publication and both exact receipts before rate consumption or password hashing; `AccountService` repeats the policy before SQL. Consent writes retain the current transaction, pending-account replacement and confirmed-account immutability. A new nullable `document_sha256` column records new fingerprints. No historical locale or digest is inferred or backfilled. The existing database update guard also protects the added column; rollback acquires an exclusive table lock before checking for evidence and refuses to remove recorded fingerprints, including a first concurrent writer.

Once approved, retain every published version and language unchanged. Text, identity, contact or translation changes require a new version and renewed explicit publication approval. Keep archived variants in the catalog so evidence links remain resolvable. Do not rewrite historical consent rows.

## Validation and scope

Integration tests use an explicit **synthetic document source** with the same real publication policy, not a Testing-mode exemption. A test can select the actual embedded publication with `LegalDocuments = null`. Existing negative request bodies are not silently repaired. Browser mocks also require exact synthetic receipts.

Only targeted Node tests, type checks, lint and formatting may run locally with the agreed resource limits. .NET compilation, PostgreSQL migration/transaction tests, generated OpenAPI comparison and real browser checks are hosted CI gates. This work does not publish licensed media, activate regional flags, prove SMTP delivery, close #108 or establish a cause for #174.
